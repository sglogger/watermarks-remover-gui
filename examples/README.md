# Example files

Small files for trying the GUI. Nothing here is secret or copyrighted; they
exist so you can watch the scanner find something and then verify it is gone.

The counts below were measured, not estimated, and the last column is what the
engine actually did with each file — including where it did nothing.

| File | What it carries | Result against engine v0.5.0 |
| --- | --- | --- |
| `sample-marked.md` | 8 invisible characters: 3× zero-width space, 2× no-break space, and one each of zero-width non-joiner, left-to-right mark and word joiner | 8 hidden characters found and removed; verified clean |
| `sample-marked.html` | 3 invisible characters (one written as the HTML entity `&#8203;`) plus an AI `<meta name="generator">` tag | 3 hidden characters and 1 marked block; verified clean |
| `sample-marked.svg` | AI creator metadata in a `<metadata>` block, plus 2 invisible characters in the markup | 1 marked block removed. **The 2 invisible characters are left in place** — the engine's SVG pipeline handles metadata but not Layer A text |
| `sample-marked.png` | PNG `tEXt` chunks naming an AI image tool (generated, see below) | metadata stripped; verified clean |
| `sample-marked.docx` | Invisible characters in the body text plus AI markers in the document properties (generated, see below) | **stays flagged.** The engine reports `docProps/core.xml: ai:Generated by` and removes nothing — see the engine limitations section in the main README |
| `sample-clean.txt` | Nothing unusual | reported clean, which is worth seeing too |

The last two rows are the interesting ones: they are kept deliberately, because
a tool that only ever demonstrates success teaches you nothing about where it
stops.

The two binary files are generated rather than committed, so this repository
carries no opaque blobs:

```bash
python3 examples/make-binary-examples.py
```

## Smoke test

With the stack running (`docker compose up -d --build`):

```bash
./examples/demo.sh
```

It checks the engine status and API contract, scans pasted text and prints every
located position, scans all example files, cleans the marked ones and re-verifies
each result, and confirms that an MP3 is refused — both by extension and when
disguised with a `.png` name.

Point it elsewhere with `GUI=http://host:port`, and authenticate with `TOKEN=…`
when the server has `GUI_AUTH_TOKEN` set. It exits non-zero if any check fails,
so it works as a post-deploy gate.
